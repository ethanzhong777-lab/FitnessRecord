# 开发流程

## 阶段 0：工程与环境

- 确认 Node、npm、微信开发者工具和测试号
- 初始化 Git 和原生小程序骨架
- 建立需求、架构、编码和验收文档
- 保证 `npm run check` 通过

退出条件：微信开发者工具能够导入项目并显示环境就绪页。

## 阶段 1：产品与视觉原型

- 确认信息架构和底部导航
- 绘制首页、趋势、计划、动作库的低保真原型
- 定义颜色、字号、间距、圆角和图标规范
- 使用示例数据完成可点击原型

退出条件：核心页面和主要操作路径经用户确认。

## 阶段 2：数据层

- 定义数据模型、校验规则和 schema 版本
- 实现 repository 与迁移机制
- 编写体重、计划和设置服务的单元测试

退出条件：增删改查、重启恢复、导入导出测试通过。

## 阶段 3：核心功能

按“体重记录 → 趋势图 → 周计划 → 动作库”的顺序开发。每个功能独立完成页面、异常状态、测试和验收后再进入下一个功能。

## 阶段 4：训练建议

- 建立可解释的规则与模板
- 对不同训练天数和器械条件做组合测试
- 增加风险提示和用户确认

AI 调整属于后续增强，不作为第一版上线条件。

## 阶段 5：真机测试与发布

- 开发者工具测试
- iOS 与 Android 微信真机测试
- 检查隐私声明、类目、包体积和素材授权
- 创建版本记录和回滚点

## 每项功能的完成定义

1. 需求与交互已确认。
2. 正常、空、错误三种状态完整。
3. 数据校验和错误提示清晰。
4. 自动检查通过。
5. 开发者工具与真机主路径通过。
6. 文档与变更记录同步更新。

## Git 约定

- `main` 始终保持可运行。
- 每个功能使用独立分支，例如 `feature/weight-log`。
- 提交信息使用 `类型: 简短说明`，例如 `feat: add weight record form`。
- 合并前至少执行 `npm run check` 并完成对应验收清单。
